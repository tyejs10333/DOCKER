# СТОПКА

**СТОПКА** - учебное мини-приложение в котором ученики повторяют историю по карточкам, проходят тесты, участвуют в дуэлях и вступают в классы, а учителя создают классы и просматривают статистику учеников.

**Опубликованное приложение:** https://stopka.site  
Полноценная авторизация в опубликованной версии происходит внутри MAX после подключения мини-приложения к боту. Для проверки в обычном браузере предусмотрены отдельные локальные режимы.

## Технологии и зависимости

- Backend: Go
- Frontend: HTML, CSS, JavaScript.
- База данных: PostgreSQL.
- Сборка и запуск: Docker
- Для публикации используется HTTPS и Caddy.

Список Go-библиотек находится в `go.mod` / `go.sum`(в папке Stopka Backend). В Go для управления библиотеками используются два стандартных файла: go.mod (аналог requirements.txt, где перечислены сам проект и нужные ему пакеты) и go.sum (аналог lock-файлов с контрольными суммами библиотек для защиты от подмены кода и одинаковой сборки на любой машине). `Dockerfile` описывает сборку Docker-образа, а `compose.yaml` - запуск Go-приложения вместе с БД.

## Локальный запуск из командной строки

### 1. Что понадобится

- Скачать код репозитория и открыть командную строку **в папке, где находятся `Dockerfile` и `compose.yaml`**.

### 2. Создать локальные настройки

**Windows CMD:**

```cmd
copy .env.example .env
notepad .env
```

.env должен задавать режим разработки(dev). остальные параметры так же можно заполнить по примеру: 
```dotenv
APP_ENV=dev
APP_PORT=8080
POSTGRES_USER=stopka
POSTGRES_DB=stopka
POSTGRES_PASSWORD=local_password
MAX_BOT_TOKEN=
TEACHER_INVITE_CODE=your_teacher_code
```


### 3. Собрать и запустить контейнеры

```bash
docker compose up -d --build
```

Нужно открыть `http://localhost:8080/healthz`: ожидается `ok`.

### 4. Проверка запросов

Для проверки реальных запросов, сохранения ответов и дуэлей необходимо использовать `APP_ENV=dev` и адреса `?dev=1`, `?dev=2`. На чистой локальной БД для полноценного сценария потребуются локальные тестовые записи.

Необходимо выполнить следующие команды:

```bash
docker compose cp learning_seed.sql db:/tmp/learning_seed.sql
docker compose exec db psql -U stopka -d stopka -v ON_ERROR_STOP=1 -f /tmp/learning_seed.sql

docker compose cp dev_users_optional.sql db:/tmp/dev_users_optional.sql
docker compose exec db psql -U stopka -d stopka -v ON_ERROR_STOP=1 -f /tmp/dev_users_optional.sql
```

`learning_seed.sql` содержит одну учебную колоду с карточками и вопросами. `dev_users_optional.sql` создаёт две локальные записи для разработки (ID 1 и 2). Эти файлы **не предназначены для prod**.

После импорта на локальном компьютере:

- `http://localhost:8080/?dev=1` - первый ученик;
- `http://localhost:8080/?dev=2` - второй ученик.

Эти режимы используют локальный API и PostgreSQL. Для проверки роли учителя нужно использовать значение `TEACHER_INVITE_CODE`, указанное в локальном `.env`.


### 5. Остановка

```bash
docker compose down
```

## База данных и данные опубликованного сервера

Схема БД находится в миграциях Go-бэкенда. Таблицы пользователей, тестовых попыток, ответов, карточек, классов и дуэлей создаются при запуске приложения.

На опубликованном сервере учебные колоды добавлялись вручную. В комплекте для локального просмотра предоставляется отдельная примерная колода. Экспорт учебных материалов из опубликованной БД можно подготовить позднее, после проверки рабочего сервера.
## Пользовательские сценарии

**Ученик - карточки.** Открывает приложение, выбирает роль ученика, выбирает историческую колоду, изучает карточки и отслеживает прогресс.

**Ученик - тест.** Открывает колоду, проходит тест, завершает попытку и просматривает результат. В основном режиме результаты сохраняются в PostgreSQL.

**Два ученика - дуэль.** Первый ученик создаёт дуэль по выбранной колоде и передаёт код. Второй ученик вводит код, после чего оба отвечают на вопросы. После завершения дуэли просматривают ее результат. 

**Учитель - класс.** Выбирает роль учителя, подтверждает её кодом, создаёт класс и передаёт код ученикам. Ученики вступают в класс; учитель просматривает состав и статистику.

## Запуск опубликованной версии

Проект уже развёрнут на отдельной виртуальной машине с HTTPS. Его рабочие настройки (`APP_ENV=prod`, настоящий токен MAX, пароль PostgreSQL) хранятся на сервере в `.env` и **не входят в репозиторий**. 

## Масштабирование
В следующих обновлениях добавим функцию добавления новых пользовательских колод: учителя смогут загружать собственные карточки с ответами. Эта функция обеспечит более гибкий подход к изучению материала и значительно увеличит базу для самих учителей. Благодаря статистике учителя анализируют какой формат тем лучше усваивается учениками и смогут использовать это при создании колод.
